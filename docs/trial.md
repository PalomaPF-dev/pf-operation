# トライアル手順

ポータル（pf-portal）への登録を待たずに、このアプリだけを立ち上げて試すための手順。
所要 15〜30分。**ポータル側の変更は不要**（登録は本運用に移すときに行う）。

## 1. データベースを用意する

[Neon](https://console.neon.tech/) でこのアプリ専用のプロジェクト（データベース）を作り、
接続文字列（`postgresql://...?sslmode=require`）を控える。
他の PF アプリとは**別のデータベース**にすること（テーブル名は `op_` 始まりだが、分けたほうが後で扱いやすい）。

## 2. Vercel にデプロイする

Vercel で `PalomaPF-dev/pf-operation` をインポートし、環境変数を設定する。

| 変数 | 値 |
| --- | --- |
| `DATABASE_URL` | 1で控えた Neon の接続文字列 |
| `NEXTAUTH_SECRET` | `openssl rand -base64 32` の出力 |
| `NEXTAUTH_URL` | デプロイ先の URL（例 `https://pf-operation.vercel.app`） |
| `PF_PROVISION_KEY` | 任意の長い文字列。**本運用ではポータルと同じ値**にするが、トライアル中は仮の値でよい |
| `MASTER_EDIT_PIN` | マスタ編集用の PIN（例 `4823`）。未設定なら編集ロックは無効 |

ブランチは `claude/pf-series-admin-app-loc6kk`。ビルドコマンド等は既定のままでよい。

## 3. ログインする

このアプリはポータル SSO でしかログインできない。ポータル登録前は、
同じ鍵で**ログインリンクを手元で発行**して入る。

```bash
git clone https://github.com/PalomaPF-dev/pf-operation.git
cd pf-operation && npm install

PF_PROVISION_KEY='2で設定した値' node scripts/make-sso-link.mjs \
  --url https://pf-operation.vercel.app \
  --login-id 12345 --name "山田 太郎"
```

出力された URL を **60秒以内に**ブラウザで開くとログインできる（期限切れなら再実行）。
この初回ログインでテーブルが自動作成される。

> ポータル登録後は、ポータルのアプリ一覧から入るだけでログインできる。このスクリプトは不要になる。

## 4. マスタを入れる

画面サンプルにあった清洲工場のライン実力を、そのまま投入するスクリプトを用意している。
**3のログインを済ませてから**実行すること（テーブルが作られていないと止まる）。

```bash
DATABASE_URL='1の接続文字列' node scripts/seed.mjs

# 残業申請まで試すなら、サンプル作業者も入れる（本番前に削除すること）
DATABASE_URL='1の接続文字列' node scripts/seed.mjs --with-sample-workers
```

入るもの：清洲工場 ／ ライン #1〜#G（ライン実力・稼働時間・始業08:00・休憩
10:00-10:10／12:10-12:50／14:50-15:00）。何度実行しても同じ状態になる。

画面から入れる場合は **マスタ設定 → 工場 → ライン設定 → 作業者** の順に登録する（PIN が必要）。

### 入れたあとにやること

- **標準人数**（マスタ設定 → ライン設定）を入れる。ここが 0 のままだと計画工数が 0 になり、
  集計の**一人当たり出来高が出ない**。
- ラインの**種別**（組立ライン／前工程）を実態に合わせる。seed は全て組立ラインで入れている。

## 5. ひととおり試す

1. **進捗・残業の入力** — 日付・工場・ラインを選ぶ。ライン実力から
   「その時刻の理論値」が自動で出る（例：#1 なら 12:00 時点で 197台）。
   実績を入れ、生産進捗と残業の要否を選ぶ。「実施」を選ぶと対象者と時間を指定できる。
2. **ダッシュボード** — その日の全ラインの最終報告・遅延・残業が並ぶ。
3. **報告履歴** — 期間・工場・ライン・生産進捗・残業の要否で絞り込む。
4. **集計** — 工場／ライン別の残業工数・達成率・一人当たり出来高と、作業者別の残業時間。CSV 出力あり。
5. **マスタ設定** — PIN を入れて解除すると、ライン実力・稼働時間・備考をまとめて直せる。

## 6. 本運用に移すとき

1. `PF_PROVISION_KEY` を**ポータルと同じ値**に変える（トライアル用の仮の値だと SSO が通らない）。
2. 独自ドメイン `operation.pf-paloma.co.jp` を割り当て、`NEXTAUTH_URL` をそれに変える。
3. ポータル側にアプリを登録する → [`portal-integration.md`](portal-integration.md)
4. サンプル作業者を削除し、実際の作業者を登録する。
5. `MASTER_EDIT_PIN` を運用のものに変える。

## トライアル中に見ておきたい点

- 理論値の出し方（休憩を実時刻で差し引く／稼働時間 H で頭打ち）が実態と合っているか。
- 入力タイミングが「進捗チェック／終業後」の2つで足りるか。
- 残業時間を**対象者ごと**に入れる粒度でよいか（全員一律でよければ一括設定だけで済む）。
- 一人当たり出来高の分母（稼働時間 × 投入人数 ＋ 残業）が、検証したい定義と合っているか。
