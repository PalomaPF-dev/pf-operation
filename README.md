# PF進捗管理（pf-operation）

生産・調達統括本部向け、**管理者専用**の進捗管理アプリ。PFシリーズの1つとして、ポータル（pf-portal）から SSO で入って使う。

各工場の生産ラインについて

1. 決められたタイミング（進捗チェック／終業後）に、**計画・理論値に対する出来高**を記録し、
2. 足りていなければ **誰が何分残業するか** を対象者を選んで申請し、
3. 期間・工場・ラインごとに **残業の発生量と一人当たり出来高** を集計する

ことを1つの画面で回せるようにする。

## 考え方（理論値の出し方）

マスタに持つのは **ライン実力（台/日）** と **稼働時間（H）**、**始業時刻**、**休憩時間帯**。

```
時間当たりの出来高 = ライン実力 ÷ 稼働時間
理論値（その時刻まで） = 時間当たりの出来高 × 正味経過時間
正味経過時間 = 始業からの経過 − その間に入る休憩（実時刻で差し引く）／稼働時間(H)が上限
```

例：ライン実力 412台/日・8H稼働・始業08:00・休憩 10:00-10:10／12:10-12:50／14:50-15:00

| 時刻 | 正味経過 | 理論値 |
| --- | --- | --- |
| 10:00 | 120分 | 103台 |
| 12:00 | 230分 | 197台 |
| 17:00 | 480分 | 412台 |
| 22:19 | 480分（頭打ち） | 412台 |

その日の計画数が実力より少なければ、計画数を上限にする。夜勤（始業が終業より後）も日跨ぎとして扱う。

## ラインの種別

| 種別 | 追いかけるもの | 数量の単位 |
| --- | --- | --- |
| 組立ライン | 日量の計画台数に対して、時間当たりの出来高で間に合っているか | 台 |
| 前工程 | 決められた時刻までに、計画された製造指図が消化できているか | 件 |

**前工程で残業を実施する場合は理由の記載を必須**にしている（画面だけでなくサーバー側でも検証する）。

## 画面

| パス | 内容 |
| --- | --- |
| `/` | 入力画面へリダイレクト（アプリを開いてすぐ進捗入力できるように） |
| `/report` | 進捗・残業の入力。日付／工場／ラインを選ぶと理論値を自動計算し、実績・生産進捗・残業の要否（実施なら人数×時間）まで登録。**グループ長マスタに載っている人は担当ラインのみ**入力できる |
| `/approvals` | 承認・申請。残業「実施」は上長が承認して生産管理部へ届き、「翌日回し」は生産管理部が許可する |
| `/reports` | 報告履歴。期間・工場・ライン・生産進捗・残業の要否で絞り込み |
| `/dashboard` | ダッシュボード。指定日の全ラインの最終報告・遅延・未報告・残業を一覧（ナビ「集計・設定」内） |
| `/summary` | 集計。工場／ライン別の残業工数・達成率・一人当たり出来高。CSV出力あり |
| `/masters` | マスタ設定（工場・ラインマスター／ライン設定／工場／グループ長／利用者・上長）。工場ごとの表で確認でき、**編集は生産管理部の管理者とポータル管理者のみ** |

### 入力画面の項目

- **入力タイミング** … 進捗チェック／終業後
- **チェック時刻** … 現在時刻が初期値（実態と違えば直せる）
- **計画数（本日分）** … その日の計画。集計の分母にもなる
- **チェック時点の実績** … 理論値が初期値（実態と違えば上書き）
- **生産進捗** … 順調／遅延（理論値との差から初期値を提案）
- **残業の要否** … 実施／翌日回し／対象外（計画完納見込み）
- 実施のとき … 理由区分・理由と、**残業の人数 × 一人当たりの時間（分）**。
  人数はラインの在籍数（投入人数）が初期値で、申請時に編集できる。
  見込み出来高 ＝ 時間当たり出来高 ×（残業人数 ÷ 在籍数）× 残業時間 をその場で表示し、
  不足分を取り戻せるかが分かる

同じライン・同じ日・同じ時刻でもう一度登録すると、その報告を上書きする（承認は取り直しになる）。

## 承認ワークフロー

| 申請 | 承認者 | その後 |
| --- | --- | --- |
| 残業「実施」 | 報告者の**上長**（**ポータルの承認者設定**からログイン時に自動反映。未設定なら生産管理部） | 承認済みが**生産管理部へ届く**（承認・申請ページの一覧） |
| 「翌日回し」 | **生産管理部**（マスタ編集権限者） | 許可されるまで確定しない |

申請者（管理者）→ 承認者（ポータルで設定された上司）→ 生産管理部、の順に流れる。
上長はポータルの利用者マスタの「承認者」を正とし、SSO ログインとプロビジョニングの両方で同期される
（マスタ設定 → 利用者・上長 での手動設定は、ポータル未設定の間のつなぎ）。
差し戻しはコメント必須。差し戻された報告は同じ時刻で再登録すると再申請になる。
入力できるラインは、**ログインID（社員番号）とグループ長マスタの社員番号の一致**で決まる
（グループ長は担当ラインのみ。マスタに載っていない管理者は全ライン）。
グループ長マスタは「ラインの残業有無の申請者」の登録であり、残業する個人の名簿ではない。

## 指標の定義

- **計画工数（人時）** … 稼働時間(H) × 投入人数
- **残業工数（人時）** … その日の最終報告の申請内容（残業人数 × 一人当たりの分）÷ 60
- **一人当たり出来高** … 実績数量 ÷（計画工数 ＋ 残業工数）
- **実績数量** … その日の**最後の報告**の実績（累計で入れるため合計ではない）

## 認証（管理者専用）

- ログイン経路は**ポータル SSO のみ**。アプリ単独のパスワードは持たない。
- ポータルの役割が `admin`（管理者）のユーザーだけがセッションを得られる。`member` は `/api/sso` で弾く。
- 権限を外された直後も入れないよう、ページ・Server Action ごとに DB の役割を都度確認する（JWT の値は信用しない）。
- マスタ（工場・ライン・作業者）の**閲覧は全管理者**、**編集は生産管理部の管理者**と
  **ポータル管理権限を持つ管理者**のみ。対象部署は環境変数 `MASTER_EDIT_DEPARTMENTS`
  （カンマ区切り、既定「生産管理部」）で変えられる。部署・管理権限はポータル SSO から連携され、
  判定は画面・Server Action の両方で行う。

詳細は [`docs/portal-integration.md`](docs/portal-integration.md)。

## トライアル

ポータルへの登録を待たずに、このアプリだけを立ち上げて試せる。手順は
[`docs/trial.md`](docs/trial.md)（Neon＋Vercel、ログインリンクの発行、マスタ投入まで）。

```bash
# ポータル登録前のログインリンクを発行する（60秒有効）
export PF_PROVISION_KEY='xxxx'
node scripts/make-sso-link.mjs \
  --url https://operation.paloma-pf.com --login-id 12345 --name "山田 太郎" --department 生産管理部

# 工場・ラインマスター（4工場33ライン）を投入する（冪等）
export DATABASE_URL='postgresql://ユーザー:パスワード@ホスト/DB名?sslmode=require'
node scripts/seed.mjs --with-sample-workers
```

> 上は**手元のシェルで実行するコマンド**。Vercel の環境変数に入れるときは、
> `postgresql://` から始まる**接続文字列だけ**を値にする（`DATABASE_URL=` や後ろの
> コマンドは含めない）。

## 開発

```bash
npm install
cp .env.example .env.local   # DATABASE_URL などを設定
npm run dev
```

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバー |
| `npm run build` | 本番ビルド |
| `npm run lint` | ESLint |
| `npm run typecheck` | 型チェック |

テーブルは初回アクセス時に `src/lib/schema.ts` が冪等に作成する（マイグレーションファイルは持たない）。

## アプリアイコン

PFシリーズ共通の作り（全面ベタの正方形＋左上→右下のグラデーション＋中央に lucide の白い線画。
角丸は表示側の CSS が付けるので画像には焼き込まない）。グリフは lucide `clock`（決められた時刻に
進捗をチェックする、というアプリの中身）、配色は茶系（`#a97142` → `#4a2c17`）。
画面側のテーマ色も同じ系統で、`src/app/globals.css` の `@theme` に `brand-*` として定義している。

```bash
node scripts/make-icons.mjs   # public/icon-192.png・icon-512.png・apple-touch-icon.png を再生成
```

ポータルのアプリ一覧用アイコンは `public/icon-192.png` をそのまま `pf-portal` の
`icons/operation.png` にコピーする。
